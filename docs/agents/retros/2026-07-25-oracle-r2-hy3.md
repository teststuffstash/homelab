# Oracle loop retro r1 — goose

## Summary (≤5 lines)
- Two structural classes dominate pain: (a) **static recipe hard-rules contradicting the dynamic TRACKS lane charter** deadlocked #47 + #66; (b) **`deepseek-v4-flash` monolithic-write truncation + fatal-error retry** consumed 3 of #1's 4 rounds.
- Wall-time is 75% one task (#8 = 193,579s/54h over just 2 green rounds); 27/32 tasks report `wall_time=0` → latency is effectively unmonitored.
- Cost/calibration telemetry is blind for 29/32 tasks (no `budget_tier` ⇒ no `calibration_error`); 27/32 cost $0 (all haiku).
- `AGENT_STRIKE` (recoverable) is mis-recorded as `worker_exit: failed`, inflating apparent failure across 3 completed issues.
- Cheap, deterministic pre-dispatch/PR-finalize gates would have removed the #47/#66 re-block cycles and #8's round-2 bookkeeping round.

## Findings (ranked, ≤6)

### F1 — Recipe hard-rule vs TRACKS lane deadlock (cross-task)
- **Evidence:** #47 blocked 3× by `.agents/fix.yaml` `chart/` ban (issue needs `chart/` edits); resolved only by human doctrine commit `3f3df8b`. #66 blocked identically — coordinator comment: *"mirrors the pre-#47 `chart/` deadlock exactly"* — by the `.github/` ban vs `track/chassis` charter; still `agent/blocked`. Both are the **same failure class** across 2 issues.
- **Mechanism:** `fix.yaml`'s forbidden-path list is static while lane ownership lives in `specs/TRACKS.md`; the dispatch gate never cross-checks the issue's `track/*` label against the forbidden list, so the conflict only surfaces *after* a worker is spawned (or, correctly, after the coordinator re-blocks — costing N reconcile passes + a human round-trip).
- **Process change:** Add a pre-dispatch policy-gate **clause in `coordinator-scan.sh`** that parses the issue's `track/*` label and the `fix.yaml` forbidden-path list; if the issue's required edit-paths intersect a forbidden path *without* a track carve-out, it labels `agent/blocked` with the exact policy conflict **before minting a session key** (one pass, not 3). Optionally machine-read the lane map by adding a `track → allowed_paths` block to `.agents/fix.yaml`.
- **Expected saving:** Eliminates #47's 3 re-block reconcile passes + 1 human doctrine commit; prevents the open #66 block; removes the recurring cost on **every** `track/deploy` & `track/chassis` issue.

### F2 — `deepseek-v4-flash` monolithic-write truncation + fatal-error retry storm
- **Evidence:** #1 (rank 1): r1 died to a 15,267-char single-call write → goose `-32602 EOF` (nothing pushed); r3 died to a 14,781-char write + a **401 "User not found" auth storm** (FU-021 class, dozens of retries, $0.036). Only r2 produced a real push. `fix.yaml` itself documents this ("round 1 of issue #1 died to a 15k-char tool call"). Deepseek is used in 4 tasks (#1, #8, #47, #52) → the risk is model-class-wide.
- **Mechanism:** (1) `deepseek-v4-flash` truncates file-recreation calls at ~15k chars; the recipe's soft `WRITE FILES INCREMENTALLY, ≲50 lines` rule **failed to bind the model** (r3 truncated again). (2) The retry policy hard-stops on budget-403 but **not** on auth-401, so a fatal error is retried until the session burns.
- **Process change:** In **`.agents/fix.yaml`**, convert the "WRITE FILES INCREMENTALLY" *instruction* into a hard rule: *never emit an entire existing file in one tool call — create a skeleton, then extend in chunks; if the path exists, use in-place edit, not recreate* (with a concrete example). Separately, extend the **launcher retry hard-stop (FU-021)** from budget-403 to **401/403** so auth fatalities stop immediately.
- **Expected saving:** #1 drops from 4 rounds to ~1–2 (only r2 was productive) → recover ~3 rounds + $0.036 + the entire 401 retry burn; prevents recurrence on all 4 deepseek dispatches.

### F3 — Wall-time is latency-dominated and unmonitored for the majority
- **Evidence:** Σ wall = 257,314s; **#8 alone = 193,579s (75.2%)** across just 2 green/clean rounds; #45 = 32,207s (8.9h) over 2 haiku rounds; #1 = 13,762s; #47 = 4,396s. **27/32 tasks report `wall_time=0`** → no latency signal at all for the bulk of the fleet.
- **Mechanism:** #8 completed in 2 rounds yet took ~54h → most wall-time is queue/reconcile/arbitration wait, not compute. And because 27/32 emit `0`, the harness can only *accidentally* notice a hang (e.g., #8) — there is no SLO.
- **Process change:** Add an **alert**: page if `wall_time_s > 4h` (catches #8 at ~1.3h into its 54h stall). Also require the coordinator ledger to **always emit `wall_time`** (don't default to 0) so the 27/32 cohort is observable.
- **Expected saving:** Would have flagged #8's 193,579s stall within ~1.3h; restores latency observability for 27/32 tasks.

### F4 — Calibration is blind for 29/32; cost≈$0 for haiku
- **Evidence:** `budget_tier=null` for **29/32** tasks ⇒ `calibration_error=null` for all of them (calibration only computed when a tier is set). Only #107/#108/#121 (`tier=md`, cap $1.00) carry `calibration_error=0.0` — and their `total_cost=0.0`, so the 0.0 is degenerate (log-ratio of ~0/0, not a validated estimate). Cost is **$0 for 27/32 tasks** (all haiku); only the 4 deepseek-containing tasks have non-zero cost.
- **Mechanism:** The budget estimator assigns no default tier, so calibration is opt-in; and when cost rounds to ~$0 the estimate isn't persisted, making `calibration_error` undefined rather than small.
- **Process change:** In the **budget estimator**, assign a **default tier to every dispatch** and persist the pre-dispatch `est_usd` separately from `total_cost_usd` so `calibration_error` (log-ratio) is defined even at ~$0.
- **Expected saving:** Restores overrun detection for **29/32** tasks (currently the loop flies blind on cost for 91% of runs).

### F5 — `AGENT_STRIKE` (recoverable) recorded as `worker_exit: failed`
- **Evidence:** #29/#42/#43 all show `worker_exit: failed` + `ci: null` + `agent/done`, but trails show `AGENT_STRIKE model=haiku error_class=unknown` with *"Resumable branch pushed"* and later **CI green + merged** (e.g., #29: `97 passed`, `GREEN at HEAD 574df83`). #29 is even double-counted as **2 failed rounds** though it completed on resume. Also model-name drift: ledger labels #47 `deepseek/deepseek-v4-flash, haiku` while the trail says `claude/haiku`.
- **Mechanism:** The ledger folds the strike event into the per-round exit status, so a *recovered* strike reads as a *failed* round; and model names aren't canonicalized between harness and ledger.
- **Process change:** Extend the **ledger `worker_exits` schema** with a distinct `AGENT_STRIKE(recovered)` vs `failed` value, and **canonicalize model names** (provider/model) at emit time.
- **Expected saving:** Stops mis-counting #29/#42/#43 (3 completed issues) as failures; enables real failure-class analysis (strikes vs genuine failures vs policy blocks).

### F6 — Unflagged `specs/` edits trigger avoidable review round-trips
- **Evidence:** #8 round 2 was **entirely** the PR-body "Spec changes:" bookkeeping fix — the diff touched 3 `specs/` files but the body said *"No spec changes"*; the reviewer (per `review.md` rule 2) called it *"the one gate that holds regardless of the pre-prod bias"* → `CHANGES_REQUESTED` → a whole extra round. #1 likewise had repeated spec-flagging friction across rounds.
- **Mechanism:** Workers land `specs/` edits but forget to update the PR-body "Spec changes:" block; the reviewer must request-changes and a round is burned on pure bookkeeping (the §2¹ side-effect in #8 was a small real change, but the *trigger* was the unflagged-spec violation).
- **Process change:** Add a **`coordinator-scan.sh` PR-finalize clause** (or finalize hook) that diffs `specs/` paths in the PR against the PR-body "Spec changes:" section and **blocks finalize / posts a pre-merge check** on mismatch.
- **Expected saving:** Removes #8's round 2 (1 round) and the whole class of bookkeeping round-trips on any `specs/`-editing issue.
