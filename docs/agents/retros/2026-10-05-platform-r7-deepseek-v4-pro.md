## Summary (≤5 lines)
CI-red is the dominant cost driver (6 of 53 round exits), all from content defects caught post-push with no pre-commit gate. No-op rounds (6 exits) trace to a single root cause: the worker does not re-read issue state after dispatch, so seat amendments and arbitration directives land silently. Budget caps are exceeded on auth-storm first rounds (oracle-fleet#778: +41% over xs cap) because 403 responses count toward the cap before the strike mechanism fires. WIP-capacity deferrals waste coordinator rides on subscription draw — the scan emits work the launcher cannot accept. High-round-count tasks (#774: 16 dispatch events, #800: 7 rounds) are dominated by mechanical errors (acceptance-block format, URL correctness, test-assertion bugs) that a recipe pre-commit checklist would catch.

## Findings (ranked, ≤6)
1. **CI-red: no pre-push gate** — 6 ci-red exits (11.3% of rounds), all content failures caught after commit+push. Every ci-red round burns API dollars (OpenRouter billed) + subscription draw. oracle-fleet#774 alone had 3 ci-red on the layout gate, each re-sending ~27K context tokens. The worker recipe has `devbox run ci` available locally; a `--pre-check` flag running it before push would catch layout/test failures at zero API cost.

2. **Worker stale-issue-read → no-op rounds** — 6 no-op exits. oracle-fleet#800 round 3: the seat posted a schema amendment at 06:28Z; the worker dispatched at 07:42Z and 08:27Z without applying it, producing no commits. oracle-fleet#774 rounds 4-5: the worker never opened `/work/context/arbitration.md`, so the arbitration directive never reached it. Both trace to the same gap: the worker entrypoint fetches the issue once at dispatch and never re-reads comments. A pre-work step that re-fetches issue comments since the dispatch timestamp would close this class.

3. **Auth-storm budget overrun** — oracle-fleet#778: xs tier ($0.50 cap), spent $0.7054. First round (deepseek-v4-flash:exacto) hit http-403-storm — the pod tried to reach a private IP (`192.168.40.31:443`), egress policy dropped it, and every 403 consumed tokens counting against the cap. The strike mechanism swapped the model, but the cap was already exceeded by 41%. An early-exit in the API retry wrapper after N consecutive 403s (N=3) would limit damage to ~3× context tokens instead of 187.

4. **WIP-capacity deferrals waste coordinator rides** — oracle-fleet#735 round 3 was deferred at 11:52Z and 11:56Z (launcher PREFLIGHT REFUSED: namespace at WIP limit), finally dispatched at 12:02Z. oracle-fleet#800 deferred at 08:29Z and 09:05Z. Each deferral = the scan emits a work unit → coordinator allocates a ride → launcher refuses → label reverted → next tick re-dispatches. The scan should check namespace pod count against `AGENT_WIP_LIMIT` before emitting a unit, per the scan's own design rule ("capacity scheduling is the scan's job").

5. **Mechanical review churn dominates high-round tasks** — oracle-fleet#774 consumed 16 dispatch events for what was ~3 rounds of real CSS engineering (grid `minmax(0,1fr)` fix, media-query coverage). oracle-fleet#800 consumed 7 rounds for a YAML data matrix + loader (~2 rounds of real data modeling). The churn rounds were: missing `<!-- agent-acceptance: begin/end -->` wrapper (#800 r1→r2), wrong MCP URLs in 4 of 8 rows (#800 r4→r5), test assertion using `or` instead of `and` (#800 r1→r2). A pre-commit checklist in `.agents/build.yaml` and `.agents/fix.yaml` — verify acceptance-block wrapper present, resolve all URLs, run test gate locally — would catch these before the reviewer.

6. **Mock/reality divergence discovered at round cap** — oracle-fleet#735 round 5 (final logic round): reviewer found `_FAKE_GH` emitted dates in the wrong format (`tests/test_publish.py:1439`). Production code was correct; only the mock was wrong. This parked the issue at `agent/blocked`, requiring human seat rounds 6-7 to merge. A CI step that runs the test suite against one real `gh api` call per run would catch mock drift before it hits the round cap.
