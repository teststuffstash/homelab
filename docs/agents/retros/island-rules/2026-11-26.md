Verdict: 17 rule files changed across 9 islands, adding 55,640 bytes net over 15 commits, and 4 of the changes widen authority.

Terms used below, all defined in [`docs/glossary.md`](docs/glossary.md):
- **Island intake** (one run of it is a *sitting*) is the unattended session that reads an island's undecided issues and gives each exactly one outcome. The outcomes include `queue` (ready for one worker run, called a *ride*), `goal` (a funded container issue with child issues) and `seat` (held for the operator).
- A **facts file** (`docs/intake/<island>.md`) holds one island's own facts. The intake rules themselves live in one shared file.
- A **lens** is a separate reviewer session that checks intake's issue bodies before they are labelled.
- **Write tiers**, as returned by the `classify_touches` classifier: `machine-merge` (the PR merges on CI plus bot review), `codeowner-merge` (the operator reads it before merge) and `codeowner-author` (no worker may write it).

The change record files intake's own rule files under the **gateway** island. That's because island intake's own files go through the gateway's sitting, as the gateway facts file now states.

## What changed

### gateway (island intake's rules: `islands/intake/rules/*`, and `docs/intake/gateway.md`)

**Intake became its own island and now sits for every island and for opted-in stack repos.**
- The rules moved from `gateway/` to `islands/intake/rules/`.
- The gateway's facts moved out of the rules into a new `docs/intake/gateway.md`. Every sitting now reads its own island's facts file.
- Each of the nine facts files gained a `## Sources` table (which read answers which question) and a `## What a ride can do` section (the recipe, write tier, CI gates and network reach). A body may no longer ask a ride for an edit its recipe bans or a read its pod can't make. What the ride can't read, intake reads and writes into the body.
- Issue bodies now come in two named shapes:
  - `spec` changes a requirement on a spec page.
  - `edit` carries exact text replacements, check commands and a `## Decision` section, with no rows table.
- The `## Key rows` form is gone. The rows lens now runs only on `spec` bodies, so an `edit` body is reviewed by the unit lens alone. Five islands default to `edit`: agent-loop, dependency-upgrades, mgmt-box, router-pair and substrate.
- The scheduled run now holds a sitting for every platform island, one after another, where it used to cover the gateway only. A stack can also turn intake on for one of its repos through its AgentStack claim. oracle/oracle-fleet has done so; its first sitting was 2026-11-22.
- The sitting now runs as its own read-only service account, `island-intake`. Before, it ran as `agent-coordinator`, which could create and delete pods and write ConfigMaps. Its permitted live reads gain Loki and the read-only Kubernetes API.
- The other files in this change are the moved lenses (`intake-escape.md`, `intake-review-rows.md`, `intake-review-unit.md`, `intake-wait.md`; paths and the `spec`-only scope only) and all eight other facts files.

Evidence: the reasons given are design reasons, not a measured event. The old service account held grants the sitting didn't need, and the coordinator image had no devbox. The file move is stated as "a move, nothing a sitting does changes". A seat ruling decided how links follow the move, and a review finding fixed the staleness alert. Class: **widens authority**, because unattended sittings now label and rule issues on eight more islands and in stack repos. The narrower service account is the one counterweight. Commit `577efa33`, #3598.

**Intake now reads a deciding fact itself instead of passing it to the worker.**
- A fact the decision rests on (which fix, how large, whether it fits) is read before the body is written. Intake uses the narrowest read that answers it, even outside the island's Sources table. Anything outside the table is reported along with a proposed new table row.
- A survey that takes several reads goes to a read-only subagent of the sitting. It is never filed as a research issue or queued as a ride.
- A deciding fact intake can't read leaves the issue untouched and is reported as `deferred (fact)`.
- A choice between means is now made on read evidence. The options not taken are written as rejected, with reasons.
- Bodies are written for "a worker that does not reason". No line may ask the worker to choose, to measure first, or to "stop and report if…". The unit lens blocks a body that has such a line.
- The other files in this change are `intake-review-unit.md` and the agent-loop, launch, retro and scan facts files.

Evidence: the commit message restates the change and gives no other reason. Class: **adds a read or tool**. Commit `5ffe7cf3`, #3570.

**Every issue body intake queues now carries an experiment.**
- An experiment is a Prometheus query with a pass threshold and a baseline, fixed before the merge. When no series can show the problem, the body says `Experiment: none — <why>` instead.
- Intake sets the label `experiment/open` with the queue labels.
- A scheduled job with no session in its path reads the verdict after the merge. On a failure it comments, reopens the issue, and removes the `agent/*` labels and `experiment/open`.
- Intake must decide a reopened issue again, whatever outcome it gave before.
- The unit lens blocks a body whose experiment fails to load or lacks a baseline.
- Each facts file marks which Sources rows an experiment may read. launch, retro and scan have none.
- The other files in this change are `intake-review-unit.md` and all nine facts files.

Evidence: no reason is given for the mechanism itself. The message records only implementation review rounds. Class: **widens authority**, because intake writes a new label and a scheduled job now reopens closed issues and strips their labels without a human. Commit `a330c03f`, #3637 (merged by a bot identity).

**An issue is sized by whether it can be split, not by counting.**
- Intake rules `goal` only when it can name two or more parts that each merge alone, leave master correct and carry their own acceptance criteria. Otherwise it rules `queue`, however long the issue looks.
- A single unit that looks bigger than a ride's budget now queues. Before, it could become a Goal, or go to the operator when it was above the Goal ceiling. The launcher's estimator now picks the budget tier.
- Intake is forbidden to write `agent-budget/*` labels.

Evidence: the message cites a stack jail's handoff (oracle 20261116-2130) but no measured event. Class: **widens authority**, because oversized single units no longer go to the operator. The budget-label ban narrows in the same commit. Commit `a2f35c1a`, #3685.

**Each row a `spec` body touches must be read with its description hidden.** Before writing a `spec` body, intake checks that each row's inputs and the requirement's own prose decide its expected result. That covers rows the body writes, rows whose result it changes, and the rows already on any requirement it adds to. Any row left undecided goes into the body, and its file goes into `Touches`. Evidence: no reason given (the title cites issue #3655). Class: **adds a rule**. Commit `14837641`, #3729 (bot).

**A body may not forbid changes inside the requirement it edits.** No acceptance line or `## Out of scope` line may ban row, legend or test changes within that requirement. An `edit` body on a spec page must list the requirement's test file in `Touches`. Evidence: a narrow issue that forbade row changes left the worker unable to clear a specs-review finding, "so the PR parked on the operator". No PR is named. Class: **adds a rule**. Commit `b136d0cd`, #3750.

### agent-loop

**The migration reviewer lens now approves a stack's test pin at or ahead of production at any distance.** Before, it approved only up to one minor version ahead. The comparison is made in each product's compatibility unit (major for Postgres, minor for Garage, Grafana and Prometheus), never across packagings. A pin behind production, or a pre-release, still gets changes requested. Evidence: the old window broke when production jumped two Garage versions (2.3 → 2.5, #3344). It is replaced by ADR-166's time offset (Renovate holds platform minor and major updates 14 days, stacks' updates 7) and a Docker image clock. Class: **widens authority**. Commit `812b016f`, #3652.

**Worker ground rules: the classifier's verdict is the rule.** The ground rules no longer list the off-limits path set. That copy was stale: it still named `scripts/`, which left the set under ADR-142. Workers now run `classify_touches` and follow its verdict. Before posting `AGENT_INFEASIBLE` on a path, a worker must run the classifier on it. Only `codeowner-author`, or a non-pin edit to a guarded file, makes the path infeasible; `machine-merge` and `codeowner-merge` paths are the worker's to deliver. Evidence: the stale list, against ADR-142. Class: **adds a rule**. Commit `a71c82f4`, #3680.

**The coordinator must park a CI-red ruling that starts no round.** A ruling on a red PR that starts no fix round and re-runs nothing must now label it `agent/blocked` with a `blocked-on:` marker. Otherwise the same red is handed to a new ride every scan tick. The coordinator is also told there is no "wait for a date" play. A `lock-intake-lint` "too new" red on a lock file the PR adds or re-locks counts as content: it gets a fix round that sets the resolver's age cutoff (e.g. uv `exclude-newer`, at least 7 days back) and re-locks, without pinning a version. Evidence: no reason given beyond a reference to issue #3426. Class: **narrows authority** (a new hold). Note that the lock-file clause directs workers to change resolver settings in project files. Commit `6d4f45c5`, #3671 (bot).

**Coordinator disposition writes now name a cross-repo member as `repo#n`.** The disposition tool now refuses a bare number for a member that lives in another repo. Evidence: measured on Goal #1640 (2026-09-16). Rows written bare for agent-runtime members were never read, so the scan re-ruled them every tick. Class: **adds a rule**. Commit `dbb13594`, #3669 (bot).
