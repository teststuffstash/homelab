# Island rules digest — week ending 2026-11-19

*The first digest, written by hand by the seat with the same script and brief the weekly
CronWorkflow will use (`agents/island_rules.py changes --since 2026-11-13 --until 2026-11-20`,
[`ISLAND-RULES-BRIEF.md`](../ISLAND-RULES-BRIEF.md)). "Island rules" are the markdown files a
launcher hands a session as its brief or rules; this week 24 files are in that set
([glossary](../../../glossary.md): "island rules").*

Terms used below. The **intake sitting** is the scheduled session that reads an island's open
issues and other inputs and gives each one ruling ([glossary](../../../glossary.md): "island
intake"): `queue` (a worker may build it now), `goal` (a tree of worker tasks), `seat` (parked on
the operator, naming the one missing fact), `close`, `standing`, and so on. **gateway/intake.md**
is that sitting's rules; each island's **facts file** (`docs/intake/<island>.md`) tells the
sitting what that island owns, what is operator-only and what a worker may touch. **Touches** is
the list of paths an issue says its work will change.

## What changed

### gateway — the intake sitting's rules (`gateway/intake.md` and its three lens briefs)

- **Review before queueing, a self-correction read, and spec-gap inputs** (`c10ac8c0`, #3378,
  operator). Before a `queue` or `goal` ruling becomes visible to workers, two separate review
  sessions now read the issue bodies the sitting wrote — one checks the whole unit, one checks the
  specification rows — and one repair pass must answer every finding by id; only then are labels
  and the ruling posted. The review never blocks the queue. The sitting also gets two new kinds of
  input: the island's own unfinished specification rows (`⚑ gap` / `🚧 WIP`), which it may turn
  into issues, and the review findings of pull requests built from issues it queued, which it
  classifies; when the same class of miss appears twice, it files an issue against its own brief,
  a lens brief or the island's facts file — the loop proposing an edit to its own rules. Finally,
  paths every issue of an island must touch for bookkeeping no longer count toward the "about five
  paths" limit for a `queue` ruling, and two authoring rules were added ("quote an existing row
  before writing a new one"; "an exception names the universal sentence it breaks").
  Creates `gateway/intake-review-unit.md`, `gateway/intake-review-rows.md` and
  `gateway/intake-escape.md`. Evidence: a scored trial — the lens briefs are "the trial's final
  minimal briefs", with the trial's cases, truth and scores under `docs/spikes/island-intake.md`
  §Run 4. Class: **widens authority** (it may now file issues against its own rules and queue
  slightly larger issues).

- **Three new islands get facts files** (`93330ef8`, #3377, operator). A sitting run for the
  `scan`, `launch` or `retro` island now has its own facts file — what the island owns, how its
  work is gated, what a worker may read — and gateway/intake.md lists them. Those sittings are
  still started by hand; nothing schedules them. Evidence: the islands are "the starting contracts"
  carved from an earlier design spike; no measured event is cited. Class: **adds a rule**.

- **A pull request parked on a human counts as a wait to re-test** (`9bb1f89a`, #3421, operator).
  When a pull request's newest review ruling says `blocked-on: human`, the sitting may now be given
  its issue as a wait to re-check (only when the `INTAKE_PR_HOLDS=1` switch is on, which it is not
  by default). For these rows the sitting writes nothing to GitHub: it gives its ruling in its
  report only. Evidence: pull request #3400 sat parked on a human for a too-new lockfile that a
  worker round could fix, and no sitting ever re-read that wait. Class: **adds a read or tool**.

- **Forwarding, and the commons** (`71b35c3d`, #3428, operator). An issue that wholly belongs to
  another island is no longer ruled or parked: the sitting retitles it to that island's title cue
  and posts one `intake: forward → <island>` comment, and the other island's sitting picks it up.
  It may do this to any bot-filed or operator-login issue whatever its age. After two forwards, or
  when an issue would bounce back, it is `seat`. A path no island claims is now "the commons": it
  goes with the island whose work it serves, and is never parked on the operator merely for having
  no owner. Parts split off for another island are filed with only that island's title and the
  original text; an input the sitting may not close stays open. Evidence: a manual sitting on
  #3424 could neither forward nor split; the operator's ruling of 2026-11-15 on #3427 (three kinds
  of ground); two review findings on the pull request. Class: **widens authority** (it may retitle
  operator-login issues and rule unowned paths instead of parking them).

- **A quoted row is still read** (`5a01b5e5`, #3509, **bot: homelab-agents-1234[bot]**). When the
  sitting copies an existing specification row into an issue, it must now read that row the way
  the rows lens will before using it, and where the row's inputs do not decide its expected
  result, add the missing column or clause instead of calling the row unchanged. Evidence: **no
  reason given** — the commit message carries only the harness and model lines. Class: **adds a
  rule**.

- **Recurring responder findings become an input** (`6c16647b`, #3544, operator). When the
  alert responder has triaged the same alert in the same namespace at least three times without
  filing anything, those findings now reach the sitting as one input; the sitting must rule the
  class on its cause and never simply apply the fix one triage proposed. Evidence: six triages in
  the week diagnosed the same pods-not-ready class on gateway worker pods and each wrote a proposed
  remedy nobody read. Class: **adds a read or tool**.

- **A ruling decides only the question it answered; an undecided choice is the sitting's**
  (`9f264e80`, #3547, operator). An operator ruling already on an issue now binds only the
  question it answered: if the issue asks a different question, the ruling does not settle it, and
  a sentence near the ruling that would forbid the work is treated as text the issue may edit. The
  body of an issue opened under the operator's login now counts as an operator ruling. And any
  choice no ruling decides — not only one an operator's text left open — is now the sitting's to
  make, picking the option that is cheaper to reverse; it parks on the operator only when no option
  is safe. Evidence: the first re-read of waits found 10 parked items, 6 of them decidable from the
  sitting's own reads; the commit states "Both edits widen what intake decides without the operator
  (operator-approved)". Class: **widens authority**.

- Wording only, recorded for completeness: `93330ef8` and `04a7aeb6` also touched the one line of
  gateway/intake.md that lists the facts files (adding the three islands, then dropping "facts only
  — not yet selector rows").

### scan, launch, retro — the three new facts files (`docs/intake/{scan,launch,retro}.md`)

These three files were created this week (`93330ef8`, above) and changed twice more; the changes
are identical across the three.

- **Gate line corrected** (`d57766e4`, #3402, operator). A sitting writing an issue for these
  islands now tells the worker that a specifications reviewer will review the island's rows, and
  that any row without evidence must carry its `🚧 WIP` or `⚑ gap` mark. The day's first version
  said no specifications reviewer read these roots. Evidence: the platform change it reflects (the
  claim now lists the islands' specs roots, #3379; workers reaching them get the pinned process,
  #3398). Class: **adds a rule**.

- **Built from the specifications, never copied** (`04a7aeb6`, #3435, operator). A sitting may no
  longer queue an issue that asks a worker to match, port or carry over the old code a component
  replaces; the old replay test families become a comparison whose every difference gets a ruling,
  not the measure of correctness. The "not yet selectable" note is gone (the selector now has rows
  for these islands). Evidence: the operator's ruling of 2026-11-15, after the first-leg Goals made
  the old replay families the correctness test and pulled a launch helper into a copy of the old
  file. Class: **adds a rule**.

### router-pair (`docs/intake/router-pair.md`)

- **The nightly certificate carry is no longer operator-only** (`f467e541`, #3526, operator). The
  facts file's operator-only list used to include "cert carry to the BACKUP"; it now names only the
  carry's identity and privileges, because the nightly run itself moved to the management box. A
  router-pair sitting may therefore rule an item about the nightly carry instead of parking it on
  the operator. Evidence: the commit moves the carry to the box under the `automation` API identity
  (its one missing privilege probed on both router nodes); the facts-file line itself carries no
  separate reason. Class: **widens authority**.

### agent-loop — the coordinator brief (`agents/coordinator/README.md`)

- **Image location** (`a342a01d`, #3330, operator). The coordinator brief now says its image lives
  on the LAN registry, never on the public GitHub registry, and that CI pushes with a registry
  token. No session decides anything differently. Evidence: both images carry the proprietary
  Claude Code binary and both packages were public. Class: **wording only**.

- **The newest arbitration directive wins** (`1a67e102`, #3460, operator). The brief now says the
  fix round takes the newest `ARBITRATE` comment across the issue and the pull request together; a
  newer ruling on either surface replaces an older one. Evidence: pull request #3337's rounds 4 and
  5 received an older issue directive instead of the newer pull-request one and did nothing.
  Class: **adds a rule**.
