## Findings (ranked, ≤6)
### F1 — Goal children are split by function without explicit ownership of shared acceptance artifacts
- **Evidence:** on 2026-11-15, #3449/PR#3450 began as six findings, but the 17:54 specs verdict made the touched preamble put the whole page in scope. Five clean worker rounds ended in `agent/blocked` at 18:14, followed by five seat commits (19:23–20:33) before approval. In the same Goal #3389, PR#3415 made six post-initial spec-only commits and no component-code repair, including findings on rows owned by another child. Goal #1060 (November 13–15) fanned out to six build children sharing `gateway/app.py`, metrics/spec/tests; the build recipe's experiments-file reset forced claim child #1067 to merge last. #1065 also produced duplicate same-content PRs #1078/#1080 and two CI sets, although the reason for the replacement PR is unknown.
- **Mechanism (falsifiable):** functional decomposition without a file/row ownership manifest lets review scope and generated acceptance files cross child boundaries; declaring one owner and serializing genuinely shared artifacts should reduce integration-only edits without reducing child test coverage.
- **One change:** extend the **coordinator README W1 ⚑ spec-gap/child-creation clause**: before queueing, each child must list its owned files and exact spec row IDs; a shared mutable row/file has one owner, with native `blockedBy` serialization when separate children truly need it. Out-of-owner findings become owned gap children rather than expanding an in-flight sibling to a whole page.
- **Expected saving:** conservatively 1–2 integration/review round-trips per coupled Goal, plus avoidance of one #3449-style seat-recovery item when ownership is the sole cause (**€3–8 in-sitting; €20–30 only when it is a lone summons**). The duplicate #1065 PR is an upper-bound opportunity, not a claimed certain saving. These worker/reviewer rides are rail 3: cash amortization is monthly fee × binding-window share (normally cents; marginal ≈$0 under headroom), while API-equivalent list×tokens is unmeasured. No paid-API saving is claimed.
- **Confidence:** high on the integration footprint; medium on causation and saving because #1065's duplicate-PR cause and actual active effort are unavailable.

### F2 — Environmental pre-PR failures still turn finished, pushed work into operator recovery
- **Evidence:** on 2026-11-12, #3301 and #3306 both stopped their first gateway rides with useful branches pushed because the managed footprint supplied a Docker daemon but no client; #3317 documents both. Each needed the environment correction/re-queue path before a PR could open. On #917, rounds 1–2 on November 11 had 25 focused and 109 full chart tests passing, but the same kind-e2e timeout reproduced on clean master. No PR opened after two rides; the operator recovered the pushed branch as PR#1044 at 22:46Z. Upstream e2e then failed once and passed on rerun.
- **Mechanism (falsifiable):** requiring every local gate to be green before PR-open converts a positively identified environment failure into another worker ride or human branch recovery, even when CI can execute the required gate. An explicit flagged-PR route should preserve the work without weakening merge checks.
- **One change:** extend the existing **worker recipe pre-PR gate skip-and-flag candidate** beyond WAN-only failures: after a branch is pushed, permit a flagged `Refs` PR only for a positively identified missing runtime capability or a failure reproduced on the unchanged clean base; name the unrun/red gate and environmental blocker, and require CI to run it before merge. All other red gates still block.
- **Expected saving:** one repeat ride and one manual PR-recovery/re-queue item per comparable event; #917 and the two gateway rides are three dated opportunities. Batch the latter as **€3–8 per in-sitting item**, or **€20–30 if one causes an out-of-sitting summons**. Rail-3 cash amortization is monthly fee × binding-window share (normally cents; marginal ≈$0 under headroom), API-equivalent list×tokens is unmeasured, and no paid-API amount is inferred.
- **Confidence:** high on events and recovery path; medium on the generalized fallback, which is conditional on CI actually running the flagged gate. Related work: targeted #3317 and #3228; neither is evidence that this generic route has deployed.

### F3 — Mechanical judgement-marker joins still consume post-PR worker and reviewer rounds
- **Evidence:** on 2026-11-14, oracle-fleet#1062/PR#1075 received a specs CR at 15:44Z and a 15:53Z fix adding ⚖ A markers/test IDs. At 20:08Z, #1065 arbitration required only renaming arm row r50.1 and its matching test/evidence IDs. Homelab #3301/PR#3324 (three November 12 specs CRs) and #3396/PR#3415 (November 15 final specs round) contain the same ⚖/row/test join class, but those rounds also had substantive findings and are corroboration rather than wholly attributable cost.
- **Mechanism (falsifiable):** workers validate semantics but do not mechanically compare the three representations before PR-open, so review remains the first exact-string check.
- **One change:** retain r11's **fix-round recipe pre-PR spec/test join check**: for every ⚖ judgement in prose or `Spec changes`, require the same ⚖-bearing row description and character-identical test case/evidence ID before opening or updating the PR.
- **Expected saving:** two more-cleanly-attributable worker corrections and two specs re-reviews on #1062/#1065; mixed #3301/#3396 rounds are excluded from the estimate. This is **rail 3 only**: cash amortization is monthly fee × binding-window share (normally cents; marginal ≈$0 under headroom), API-equivalent list×tokens is unmeasured, with no rail-1 or paid-API saving claimed.
- **Confidence:** high on recurrence; medium on extrapolation beyond these spec-shaped tasks.
