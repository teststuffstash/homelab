## Findings (ranked, ≤6)

### F1 — An approved, green, auto-merge-armed PR that goes `BEHIND` is invisible to every clause; 103 h of post-approval idle this week

**Evidence.** `homelab` master lane, both PRs from the 2026-10-02 platform batch:

| PR | bot APPROVED | auto-merge | `ci` | merged | post-approval idle |
|---|---|---|---|---|---|
| [#2173](https://github.com/teststuffstash/homelab/pull/2173) | 2026-10-02T18:07:21Z | armed (bot, squash) | SUCCESS | 2026-10-04T19:24:45Z | **49.3 h** |
| [#2174](https://github.com/teststuffstash/homelab/pull/2174) | 2026-10-02T18:18:00Z | armed (bot, squash) | SUCCESS | still OPEN | **54.0 h and counting** |

`#2174`'s `updatedAt` has not moved since 2026-10-02T18:18:37Z and its `mergeable_state` reads `behind` at observation time — 54 h with zero touches. The issue-side number agrees independently: [`homelab#2167`](https://github.com/teststuffstash/homelab/issues/2167) carries `standing_stall_seconds: 194416` (54.0 h) in the bundle. This also fully explains the two platform wall-time outliers, which the blind-spot rule required me to cross-check rather than call slow: `homelab#2170` `wall_time_s = 182358` (50.7 h) is *exactly* PR#2173 created→merged, of which 1.4 h was worker+review and **97 % was merge-queue idle**; `homelab#2036` (48.7 h) is `major/awaiting-human` gate time, i.e. by design.

**The lane did not resume when its head cleared.** [`homelab#2203`](https://github.com/teststuffstash/homelab/issues/2203) (filed 2026-10-04T05:55Z) hypothesises oldest-first starvation. New evidence sharpens it: `#2173` (the lane's oldest merge-ready member) cleared at 19:24Z on 10-04, and `#2174` *still* received no update in the following 9 h. So this is not only head-of-lane starvation — `agents/update-pr-branch.sh` leg 1 is not delivering on this lane at all.

**Mechanism (falsifiable).** Auto-merge is armed but GitHub's strict-up-to-date rule holds it while the PR is `BEHIND`; the only actor that can clear `BEHIND` is the updater's leg 1; and the state `armed ∧ bot-APPROVED ∧ ci green ∧ BEHIND ∧ unmoved` matches **no** scan clause — the `agent/review` phantom clause in the state-machine table fires only when there is *no* open PR, so an open-but-frozen PR is the same terminal sink as homelab#928, one state later. Falsifier: if the updater's pass log shows leg 1 picking `#2174` and 422-ing, it is a 422 bug, not a clause gap.

**Process change.** Extend the existing `agent/review` phantom-reconciliation predicate in `agents/coordinator-scan.sh` by one disjunct: an **open** PR that is auto-merge-armed, bot-APPROVED at head, `ci` green, `mergeStateStatus == BEHIND` and `updatedAt` unmoved past `C4C5_PERSIST_S` emits a unit (the same `C4C5_PERSIST_S` threshold the table already uses for the other two phantom cases). One predicate, one existing clause, no new state.

**Expected saving.** Rail 1. `#2173` was released only by an operator review-dismissal at 2026-10-04T18:50:54Z — an out-of-sitting summons (E ≈ €20–30); `#2174` still owes one; `#2203` explicitly asks for a human to read the updater's pass log (a third). **€40–90/week** at 2–3 avoided summons, plus ~103 h/week of merge latency removed from the loop's critical path. Confidence: high.

### F2 — The round cap parks the loop and the operator seat finishes the job — and the handed-over work is the cheapest kind to automate

**Evidence.** [`oracle-fleet#735`](https://github.com/teststuffstash/oracle-fleet/issues/735) → [PR#810](https://github.com/teststuffstash/oracle-fleet/pull/810). The coordinator parked at 2026-10-04T16:32:46Z: *"This PR has now consumed all 5 logic rounds (ADR-127) … no 6th round is authorized"* — and its own "For the human" paragraph describes the remaining work as *"add `split("T")[0]` (or equivalent) to `_FAKE_GH`'s date emission at `tests/test_publish.py:1439`, plus an equal-calendar-date fixture … Production code itself needs no further change."* The operator seat then worked 2026-10-04T18:25:40Z → merge at 20:27:55Z (**2 h 02 m**), hand-authoring rounds 6 and 7. The same pattern, one stack-week earlier in the same deep-dive set: [PR#780](https://github.com/teststuffstash/oracle-fleet/pull/780) ran to **round 16** and closed only on a codeowner read *"(jail seat, on the operator's delegation 2026-10-03)"* that approved while explicitly listing four unfixed gaps.

**Mechanism.** The cap is a bound on rounds, not on *residual size*. A park at round 5 with a two-line residual and a park at round 5 with a redesign residual produce the identical action — hand the whole PR to a human. The park comment already computes the residual in prose; nothing acts on it.

**Process change.** In the coordinator brief's §arbitrate play, make the round-cap park branch on the residual the comment already writes: when the final re-review's blocking findings are confined to the PR's **own test harness or fixtures** (no production-code change named), the park authorises exactly one fixture-only round instead of `agent/blocked` — a bounded, single-use exemption in the same shape ADR-127 already grants strikes and no-op rounds, not a raised cap.

**Expected saving.** Rail 1, the only item on this list that reaches a full seat-hour. The observed event cost E + 2 h 02 m ≈ **€220** for one park in one week. One avoided park ≈ €20–30 (the summons) plus whatever seat time it consumes. Confidence: high on the cost, medium on how often the residual will qualify (1 of 1 observed).
Related: [`homelab#2169`](https://github.com/teststuffstash/homelab/issues/2169) (directive grammar burns one round per instance of a class — PR#780 R6–R9 fixed the same bare-`1fr` grid bug four times).

| PR#2174 R2 ([arbitrate 2026-10-02T17:05:54Z](https://github.com/teststuffstash/homelab/pull/2174)) | `ADR-103 ratchet: clause files changed with NO replay fixture change` | CI ratchet |
| PR#2174 R3 ([arbitrate 2026-10-02T17:31:28Z](https://github.com/teststuffstash/homelab/pull/2174)) | `index-currency` — fixture index not regenerated (598 passed, 1 failed) | CI ratchet |
| PR#809 R2 ([arbitrate 2026-10-04T09:01:12Z](https://github.com/teststuffstash/oracle-fleet/pull/809)) | `spec-evidence-lint` ratchet H, "step without evidence" | CI ratchet |

Against the whole-population denominator that is 5 of 53 round entries (9.4 %) — comparable to the entire ci-red class (6/53) and the entire no-op class (6/53).

**Mechanism.** Workers do run CI locally — the `#778` strike log shows `bash scripts/ci.sh --stages python` — but they run a *stage subset*, and every ratchet above lives outside it. The ratchets are deterministic and pre-push-checkable; they are being discovered by the gate instead.

**Process change.** One line in the dispatch recipe of the coordinator brief: before pushing a round, run the repo's ratchet steps (not a stage subset) and, when the diff touches `specs/`, update the PR body's `Spec changes:` section in the *same* commit — then add that as one required row in the `<!-- agent-acceptance -->` block the reviewer already audits, so a missing entry is caught at round 1 instead of round N.

**Expected saving.** Honest denomination: this change saves **no rail-1 operator time**. ~5 machine rounds/week on rail 3 (subscription, amortized — cents) plus ~5 × ~25 min of loop wall-time. Its real value is indirect: PR#780's two PR-body rounds are two of the sixteen that produced the codeowner escalation in F2. Confidence: high.
Related: [`homelab#2168`](https://github.com/teststuffstash/homelab/issues/2168) files the downstream edge (a body-only fix never re-triggers review); this finding is the prevention, not that edge.

### F4 — Worker-authored gates are green-by-construction, so the reviewer becomes the test suite and each discovery costs a full round

**Evidence.** Two deep-dive tasks, six instances, CI green over every one:

- PR#810: the park ruling names the class itself — *"this is exactly the mock/reality divergence class that burned rounds 2-4, and no existing fixture exercises the equal-date case, **so CI stays green over it**."* Rounds 2, 3, 4, 5 and the park were all this class. The reviewer could only find them by building its own harness: *"Executed `scripts/snapshots-prune.sh` directly (fake `mc`/`skopeo`/`gh` harness built from this PR's own `_FAKE_MC_SNAPSHOTS`/`_FAKE_SKOPEO`/`_FAKE_GH` …) against two scenarios the existing fixtures don't cover."* The operator's round-6 audit then found three more: *"three Rule 4 / base-of-served fixtures asserted substrings of the step header and were vacuous."*
- PR#780: `ls_verify` ANDed three independent substrings — *"the entire LS § 13 lg 3 demo block in connect.html could be deleted without this check failing"*; the standing-line drift check *"compares two independent presence-booleans against a third, test-local hardcoded constant"*; the round-1 `collision` skip was a fail-open gap; and the approving review still noted `test_standing_line_test_exists` *"only checks `hasattr`"*.
- **The cost continues past merge.** PR#780 merged 2026-10-03T07:08:16Z with three fail-open skips the codeowner listed but did not block on; [#786](https://github.com/teststuffstash/oracle-fleet/issues/786), [#787](https://github.com/teststuffstash/oracle-fleet/issues/787) and [#788](https://github.com/teststuffstash/oracle-fleet/issues/788) were filed at 07:24–07:25Z — **three new tasks within 17 minutes of the merge**, all against the gate that had just passed.

**Mechanism.** The acceptance contract asks for a check that catches X; the cheapest implementation that satisfies both the contract and CI is one that asserts presence rather than behaviour, and nothing in the loop ever runs the new gate against an input it should reject. Issue #774's own title already states the right procedure — *"catch the mobile defects **red**, then fix them"* — it simply is not in the acceptance contract.

**Process change.** Add one required row to the `<!-- agent-acceptance -->` block for any PR that introduces or edits a check/gate/rule: a **red-first receipt** — the check's output on a deliberately-broken input (red) and on the fixed input (green), pasted. Make a missing receipt a round-1 blocking finding in the reviewer rubric (`.agents/review.md`, the rubric the PR#810 park ruling cites by name), which replaces N late discoveries with one early one.

**Expected saving.** Rails 2–3 directly (4–7 machine rounds/week, cents amortized) **plus** one rail-1 item: this class caused the PR#810 park, so avoiding it is worth ~1 E (**€20–30**) per avoided park. Also removes ~3 post-merge rework dispatches/week. Confidence: high (6 instances, 2 tasks, 1 week).

### F5 — An egress-policy drop is recorded as `http-403-storm`, so the week shows `infra_failure_events: 0` and the fleet-fault channel cannot fire

**Evidence.** [`oracle-fleet#778`](https://github.com/teststuffstash/oracle-fleet/issues/778) round 1: `AGENT_STRIKE: model=deepseek/deepseek-v4-flash:exacto error_class=http-403-storm round=1` (2026-10-03T12:55:38Z). The operator's platform note 15 minutes later gives the real cause: *"Ride pod `agent-oracle-fleet-issue-778-r1` (on nx-01) sent TCP SYNs to `192.168.40.31:443`. The policy dropped them (`POLICY_DENIED`) … the mcr.microsoft.com pull-through mirror … serves plain HTTP on :80."* Not auth — node egress policy. Consequences, all checkable: the bundle's whole-window `infra_failure_events` is **0**; the strike swapped the *model* (deepseek → haiku) for a network fault; and the row carries `total_cost_usd 0.7054`, **23 % of the window's entire measured paid-API spend ($3.0613)**, attributable to that round as the row's only paid-tier model (rounds 2–3 were haiku/sonnet, untracked). The class is not new: the bundle's own late-arrival sample carries [`sleep-tracking#67`](https://github.com/teststuffstash/sleep-tracking/issues/67) — *"🚨 AgentWorkerEgressDropped: … k3d node pulls hit egress policy, worker gave up without the gate"*, 2026-07-28 — so a named alert for exactly this already exists.

**Mechanism.** The strike taxonomy folds any connection-refused/denied result into the HTTP-403 bucket. Because the fleet-fault STRIKE channel keys on *"same `error_class=` … on ≥2 distinct issues inside 24h"*, an egress fault can only trigger it by being misclassified the same way twice — and even then it would file against the wrong gate.

**Process change.** Add one `error_class` to the `AGENT_STRIKE:` taxonomy in the launcher (`agent-session.sh`, the component the strike comment is emitted by): `egress-denied`, matched on `POLICY_DENIED`/connection-refused before the HTTP-status fallback, routed to `infra` rather than `auth` so the swap logic retries the same model on a different node and the existing `AgentWorkerEgressDropped` alert — not the model router — owns it.

**Expected saving.** Rail 2: **$0.705 observed** on the single in-window instance (a storm round that ran full CI stages before dying). Rail 1, contingent: restores the fleet-fault path that converts a recurring node fault into one filed issue instead of N silent parks — the July precedent shows it recurs across quarters. Confidence: medium (one in-window instance + one dated precedent).

### F6 — A policy-waiting PR is a CI perpetual-motion machine: 53 workflow runs in 7 days, all red on the same step

**Evidence.** [`homelab#2100`](https://github.com/teststuffstash/homelab/pull/2100) (mermaid v12), open since 2026-09-29, ruled nine separate times as *"ADR-143's designed red … nothing in this repo can shorten it"* — the wait is the upstream v12.0.1 publication. Inside the window, on that one branch: **21 force-pushes** (Renovate rebasing onto master ~4–5×/day), **22 red `CI` runs**, **31 `renovate-approve` runs**. Every red is the identical single step, `lock-intake-lint` → `FAIL vulnerable lodash-es@4.17.23`, whose own output carries the instruction not to fix it. The same wait has already churned through two PR identities (#2032 closed → #2100 re-proposed). The *ride* half of this cost was fixed in-window (see Predecessor, #2147); the *CI* half was not.

**Mechanism.** Renovate's rebase cadence is lane-independent, so a PR whose exit condition is an upstream release rebases — and re-runs a full CI matrix — on every master push, indefinitely.

**Process change.** `renovate-global.json`: give the ADR-143 waiting class (`major` + a red `lock-intake-lint` intake) `rebaseWhen: "conflicted"` instead of the default behind-base rebase, so a PR that cannot go green stops buying a CI matrix per master push and resumes normal rebasing the moment the version moves. This is one rule in the lane work already specified by [`homelab#1988`](https://github.com/teststuffstash/homelab/issues/1988) ("Renovate lanes by BLAST CLASS in `renovate-global.json`", rank 5, open) — an addition to that scope, not a new workstream.

**Expected saving.** Stated honestly: **no rail 1–3 saving.** The resource is self-hosted runner capacity — ~53 workflow runs/week removed from one PR — and the queue latency those runs impose on the same runners the merge path in F1 depends on. Confidence: high on the counts, medium that runner contention is material.
