# platform loop retro r5 — claude-sonnet-4-20250514
## Summary (≤5 lines)
The deep-dive set (ranks 1–8) reveals three dominant cost patterns: deepseek-v4-flash burns a first round on ~40% of dispatches before haiku cleans up; goose-32602-truncation is the single most common harness death (10+ occurrences, fleet-strike #1707 already filed); and CI-ratchet bookkeeping (missing replay fixtures, index-currency drift) consumes 1–2 rounds per platform-path task before substantive review begins. The oracle-fleet#304 repetition-loop (5 identical harness deaths, zero PR) shows the STRIKE-channel detector has a blind spot when all rounds are "round 1." Budget-tier sm ($0.50) underestimated platform-path work on 4 evidenced tasks. Cross-repo trails for sleep-tracking and oracle-fleet stacks are unreachable (repos do not exist under teststuffstash). One win: circles#77 landed in 1 round with first-approval on a well-scoped single-file doc change.

## Findings (ranked, ≤6)

**F1 (rank 1): deepseek-v4-flash burns round 1 on ~40% of dispatches, haiku reliably cleans up**
- **Evidence**: homelab#913 r1 (nonzero-exit-1), homelab#625 r1 (nonzero-exit-1, plus model attribution bug in AGENT_STRIKE), homelab#866 r1 (nonzero-exit-1), homelab#617 r1 (nonzero-exit-1), oracle-fleet#397 r1 (no-output), homelab#1151 r1 (budget-403). In every case, the next chain entry (haiku) completes clean. The pattern is consistent: deepseek-v4-flash is the primary chain entry, it fails inside 11s–2min at $0.00–0.02 before any billable work, and the fallback haiku succeeds. On homelab#625 the strike record mis-attributed the model as `haiku` when the ride stats prove it was `opencode-go/deepseek-v4-flash` — a second-order defect that could route the fallback backwards.
- **Mechanism**: The chain-rotation in agent-session.sh always tries deepseek-v4-flash first. The model has an elevated rate of early-exit failures (nonzero-exit-1 from UnknownError, no-output from server-side errors, budget-403 from key exhaustion) that are NOT infra-class strikes because they're model-specific, not rail-wide. Each consumes a round before the fallback succeeds.
- **Process change**: In `agents/agent-session.sh`, add a pre-dispatch liveness probe for the primary chain entry: a single trivial prompt (e.g., "OK") before the full ride. If the probe fails, skip to the next chain entry WITHOUT consuming a logic round. The probe costs ~$0.0003 in tokens (rail 2 only).
- **Expected saving**: 1 round per deepseek-primary dispatch (evidenced: 6+ tasks in deep-dive set alone). AGENT_STRIKE comments that escalate to human review are out-of-sitting summons: €20–30 each. In-sitting fallback-swaps that don't escalate save €3–8 each (operator trims the strike record during the sitting). Conservative estimate: €60–120/month in operator time + $0.12–0.30/month in wasted API calls (rail 2). Evidence origin: homelab#625 (most documented case).

**F2 (rank 2): goose-32602-truncation is the single most common harness death across the fleet**
- **Evidence**: homelab#791 r2, homelab#1205 r1, oracle-fleet#397 r2 + r6, circles#32 r1, oracle-fleet#272 r1, circles#19 r1, sleep-tracking#123 r1 + r2 (deepseek-0731 variant). 10+ occurrences across 7+ issues. Fleet-strike issue #1707 already filed. All occur on deepseek-v4-flash variants. Exit is always `harness-death` at $0.00 (pre-billable), meaning the context assembly itself exceeds the model's window before any tool call.
- **Mechanism**: The coordinator's context assembly (recipe + repo structure + issue body + diff) exceeds deepseek-v4-flash's effective context window. The harness detects truncation at dispatch time and dies. The model-id → context-window mapping is not consulted during dispatch.
- **Process change**: In `agents/estimate_budget.py` §Tunable assumptions, add a per-model context cap table keyed on `model_id.base_id()`. When the estimated context tokens exceed 80% of the model's known window, flag the model as unsuitable and skip to the next chain entry. The table ships with one entry: `deepseek/deepseek-v4-flash → 65536` (the known effective window before truncation). This gates at dispatch time (coordinator-scan.sh chain-rotation), not at budget-estimate time.
- **Expected saving**: 1 round per truncation event (10+ evidenced). Each is an AGENT_STRIKE → potential escalation: out-of-sitting summons €20–30 when a human must clear the park. Evidence origin: #1707 (fleet-strike, aggregates many rows — standalone-honest).

**F3 (rank 3): CI-ratchet bookkeeping consumes 1–2 rounds before substantive review begins**
- **Evidence**: homelab#625 r2 was a no-op (authored replay fixture, never pushed — `salvage_push` returned early because `pr_url` was set); r3 re-did the same work; r4 was index-currency metadata. The first substantive reviewer verdict arrived at r4. homelab#1041: r2 fixed MCP_PRELUDE placement (replay region visibility), r3 fixed MODEL unbound variable in fixture env. homelab#913: rounds 8–10 went to fixture restructuring (transcription→extraction), docblock metadata, and `pins:` key format. In all three cases, 1–2 rounds were spent on mechanical CI-ratchet artifacts (missing fixtures, stale index, variable scoping) that a pre-push check would catch.
- **Mechanism**: The ADR-103 ratchet requires replay fixtures for clause changes, but the worker recipe does not enforce a pre-push `clause-replay` run. Workers discover fixture gaps only when CI goes red. The index-currency check (`README §Index is stale`) is a separate CI step that fails independently, so a fixture-added-but-index-not-updated push burns a second CI-red round.
- **Process change**: In `.agents/fix.yaml` (the worker recipe), add a pre-push gate clause: "Before `git push`, run `devbox run clause-replay && devbox run clause-replay --index --write` (the index-write is idempotent when up to date). If either fails, fix before pushing." This is a recipe text change, not a code change. The `--index --write` flag already exists (cited in homelab#625 r4 directive).
- **Expected saving**: 1–2 rounds per platform-path task that touches replay regions (3 tasks, 5+ rounds evidenced). These are in-sitting trims: €3–8 per avoided re-round. Evidence origin: homelab#625 (origin issue — process-change parent).

**F4 (rank 4): repetition-loop detector didn't fire on oracle-fleet#304 — 5 identical deaths, zero progress**
- **Evidence**: oracle-fleet#304: 5 rounds, all on deepseek-v4-flash, all exit `harness-death` / `repetition-loop`, all round 1 (round counter never advanced), 20933s wall, $0.00 cost (untracked), no PR created. Zero progress across 5 pod spin-ups. The STRIKE-channel rule ("second strike with identical (model, error_class) routes to agent/error") should have tripped, but every round was "round 1" — the round counter didn't advance, so the strike-dedup logic never saw a second occurrence.
- **Mechanism**: The coordinator dispatches "round 1" when there's no resumable branch. Since every repetition-loop death left no branch, every re-dispatch was a fresh "round 1." The strike counter keys on (issue, round) or doesn't aggregate across same-round-number dispatches. The identical (model, error_class) pair occurred 5 times without triggering the STRIKE-channel path.
- **Process change**: In `coordinator-scan.sh`'s strike-dedup logic (the MODEL rule cited in README.md excerpt), count strikes per (issue, model, error_class) regardless of round number. When the same (model, error_class) appears on the same issue ≥2 times, route to `agent/error` STRIKE-channel path even if the rounds were all numbered "1." This covers the no-branch-left case.
- **Expected saving**: 4 rounds + pod spin-ups per repetition-loop event. Each is an out-of-sitting escalation (AGENT_ERROR label → human must clear): €20–30. Evidence origin: oracle-fleet#304 (origin issue, but repo unreachable — cited from ledger row).

**F5 (rank 5): budget-tier sm ($0.50) systematically underestimates platform-path agent work**
- **Evidence**: homelab#1041: tier sm, cap $0.50, actual $0.5245 (exceeded, calibration_error 1.049). homelab#778 r4: budget-403 on poolside/laguna-s-2.1:free. homelab#892 r1: budget-403 on deepseek-v4-flash. homelab#779 r1: budget-403 on deepseek-v4-flash. homelab#1151 r1: budget-403 on deepseek-v4-flash. All 5 tasks touched `agents/**` paths (the most expensive tier — codeowner-gated, multi-round review). The estimator's DEFAULT_ROUNDS=3 doesn't match the actual 5-round logic ceiling (ADR-127), and the DEFAULT_CONTEXT_TOKENS=20000 may undershoot for platform tasks that carry large recipe contexts.
- **Mechanism**: `estimate_budget.py` uses conservative defaults designed for general fixer tasks. Platform-path tasks (`agents/**`) consistently need more rounds (reviewer scrutiny is higher on codeowner-gated paths) and carry larger context (the coordinator brief itself is long). The $0.50 sm tier is calibrated for ~3 rounds × 20K tokens; platform tasks routinely need 4–5 rounds × 25K+ tokens.
- **Process change**: In `agents/estimate_budget.py`, add a path-based multiplier: when the issue's `Touches:` footprint includes `agents/**`, multiply the round estimate by 1.5 (ceil to integer). Raise DEFAULT_ROUNDS from 3 to 4 (the midpoint between the old 3 and the ADR-127 ceiling of 5). Both are tunable assumption changes in the existing `§Tunable assumptions` block, not new logic.
- **Expected saving**: Prevents budget-403 on ~4 evidenced tasks. Budget-403 causes a re-dispatch with haiku (different model): the wasted deepseek round costs $0.02–0.05 (rail 2 only — paid API). The re-dispatch itself is in-sitting (coordinator handles it automatically): €3–8 operator time per trimmed re-dispatch. Honest: this change saves only rail 2–3; it does not remove an operator-touch class. Evidence origin: homelab#1041 (origin issue).
