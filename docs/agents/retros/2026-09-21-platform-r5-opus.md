# platform loop retro r5 — claude-opus-5[1m]

## Summary (≤5 lines)
The loop's biggest repeated cost is not bad code — it is **rides spent deciding that nothing happened**: 20 arbitrate rulings on rounds that never ran, 11 arbitrate rides on two master-origin reds, and a stale-label reconciler that blinds the retro's own input (4 of 8 deep-dive slots were spent on tasks that merged).
Worker quality is a distant second, and it is concentrated: 22% of all 158 rides are infra strikes, 26/59 of them on the unsuffixed `deepseek/deepseek-v4-flash` id vs 0/6 on `:exacto`.
The budget estimator is sized for 3 rounds while the loop runs a median of 4 and a bound of 5 — the sm tier's mean calibration error is 9.5× md's.
Predecessor retros did **not** reduce rounds/issue (2.45 → 5.17); they converted parks into completions, which by this brief's own cost model is a good trade.
Ledger caveat, stated once: per the known blind spots I ignored `reviewer_rounds`, treated `total_cost_usd: 0.00` as untracked, counted review rounds from trails, and cross-checked every long wall against PR open→merge before calling it idle.

## Findings (ranked, ≤6)

### F1 — The retro's own input is corrupted: `agent/blocked` is excluded from the reconciler by the same selector that protects it from dispatch
**Evidence.** Of the 11 reachable ledger rows labelled `agent/blocked`, **7 have a MERGED PR**: homelab#913/PR915, #1041/PR1058, #625/PR631, #791/PR802, #270/PR275, #148/PR150, circles#77/PR79. Live labels today: #913, #625, #270, #148 are **CLOSED with a merged PR and still carry `agent/blocked`** (26, 33, 41 and 44 days stale). Only #1041, #791 and circles#77 reconciled to `agent/done`. The pain-rank sorts on `terminal_label`, so ranks **1, 5, 11, 14, 16** are mislabelled successes — half the deep-dive set. homelab#1651 (filed 2026-09-14, still OPEN) reports the same reconciler dead.
**Mechanism (falsifiable).** Not a closing-keyword miss: #913 closed at `16:50:41Z`, one second after PR915 merged, so the mention edge worked and C6 was merely skipped. The README `agent/blocked` row says the label is *"Excluded from the C4/C5 predicate by the selector, not by assumption."* The merged-terminal reconciler (IL-T28, #1106) rides the C4/C5 scan class — so the selector that stops a human gate being re-dispatched also stops it being *reconciled*. Falsifier: a CLOSED `agent/review` issue (not excluded by that selector) should reconcile fine; the two rows that did reconcile carry `agent/done`, consistent.
**Process change.** In the README state machine's `agent/done` row, split the exclusion: `agent/blocked` is excluded from **dispatch**, not from **reconciliation** — the merged-terminal clause reads CLOSED issues carrying `agent/blocked` past `C4C5_PERSIST_S` on issue state alone.
**Expected saving.** Rail 1: a stale `agent/blocked` holds every sibling through the ADR-097 footprint intersection (README, IL-T16), so each stale label is a silent dispatch block a human eventually unsticks — 4 live instances in homelab alone. Rail 3: recovers ~50% of each retro's deep-dive budget, currently spent auditing merged work.

### F2 — A master-origin red is arbitrated once per PR; the FU-115 round counter fires before the ci-cause class is read
**Evidence.** `2026-09-09T16:14:09/:24/:28Z` — the identical `ARBITRATE (ci-red, FU-115) … CI still red … (cap 3)` escalation fired on **PR1545, PR1541, PR1540 within 19 seconds**, all against the same master red (#1565, `ci/OpenTofu formatting (fmt -check, all roots)`, `class=infra`). Each then needed a **second, corrective** arbitrate ride to rule "the red is not this PR's" (PR1545 16:32:35Z, PR1540 16:42:03Z). The whole sequence repeated `2026-09-11T18:41:03/18:43:45/18:43:50Z` on the same three PRs (now "cap 5"), plus a corrective at 18:47:33Z. PR1541 received the verbatim same ruling on **three separate days** (09-09, 09-10, 09-11). Total: **11 arbitrate rides on 3 PRs from 2 reds.** Wall-time cross-check: ledger 90.7h / 70.1h / 69.1h vs PR open→merge 129.8h / 71.0h / 70.0h, 98.4–98.6% idle — genuine hold, not slow work.
**Mechanism (falsifiable).** The `ci-red` clause evaluates the round counter before reading `ci-cause … class=`, so an infra red is indistinguishable from a content red at the moment the counter escalates. The brief's own "one fleet fault, not N parks" rule lives in the `agent/error` row — downstream of the counter. Falsifier: an infra-class red on ≥2 PRs that produced one fleet ruling and zero counter escalations.
**Process change.** Reorder the precondition in the README `agent/error` row's FLEET-level trigger so the `ci-red` clause reads `class=` **first**: `class=infra|environment` on ≥2 distinct PRs in 24h emits the fleet ruling instead of counting a round. The correct template already exists verbatim — PR473's `AGENT_ERROR: infra-class CI red on 2 PRs … one fleet signal instead of N parks` (2026-08-17).
**Expected saving.** 11 arbitrate rides → 2 per incident (2 incidents in 3 days) — rail 3, cents. The real saving is ~50h × 3 PRs of held wall-clock per incident, and it removes the N-way park that F1's stale labels then inherit.

### F3 — 20 arbitrate rides spent ruling that a round did not run
**Evidence.** 20 rulings across **9 of 21 reachable PRs (43%)**: PR1540 ×4, PR1541 ×4, PR1208 ×3, PR1545 ×2, PR1273 ×2, PR631 ×2, PR915, PR1462, PR473. Two sub-classes:
(a) *a pod ran, HEAD unmoved* (FU-115b/FU-147) — e.g. PR915 19:03:41Z, PR631 15:37:36Z and 15:50:14Z.
(b) *a ruling was posted and no pod ever ran* — PR1541 21:01:16Z "dispatching the ride the last ruling never got … what was missing is a worker"; PR1540 2026-09-12T14:21:06Z "ordered round 7 and was **never executed**: no worker pod exists, no `agent-ride` check-run, no run-stats, no commit … and no deferral was recorded either" — **18.6h of wall** (09-11T19:42 → 09-12T14:21).
PR1208's two consecutive no-ops escalated to `AGENT_ERROR: second consecutive no-op fix round … escalated to the operator` — an out-of-sitting summons.
**Mechanism (falsifiable).** Detection is post-hoc and LLM-mediated (read the stats comment, then compare HEAD), but the remedy is always mechanical and the rulings say so verbatim: *"the directive stands unchanged."* Falsifier: a no-op whose correct remedy was a *changed* directive.
**Process change.** Add a deterministic `head-unmoved` unit class to `agents/coordinator-scan.sh`'s clause set, alongside the `ci-red` / `arbitrate` / `merge-conflict` classes its `state-fp:` markers already emit, which re-dispatches the **unchanged prior directive at the same round number**. The README invariant already defines the state ("a no-op round — stats posted, HEAD unmoved — is not a logic round"); this gives it a clause instead of a judgment.
**Expected saving.** **Rail 1: ~€20–30** — one observed out-of-sitting escalation (PR1208) removed, and sub-class (b) is the class that stalled PR1540 for 18.6h. Rail 3: ~14 of 20 arbitrate rides plus the ~14 wasted worker rides behind them.

### F4 — Round-1 model roulette: 22% of all rides are infra strikes, concentrated on the unsuffixed deepseek id
**Evidence.** 34 of 158 rides (22%) exit non-clean/non-ci-failed, and **20 of 33 round-detailed tasks burn their first attempt** on one. By model: `deepseek/deepseek-v4-flash` **26/59 = 44%**; `-0731` 2/3; `opencode-go/…` 2/3 — vs `haiku` 9/81 = 11%, `sonnet` 0/2, **`deepseek/deepseek-v4-flash:exacto` 0/6**. All **9** `goose-32602-truncation` events and all **6** `http-401-storm` events are on unsuffixed or `-0731` ids; none on `:exacto`.
**Mechanism (falsifiable).** `estimate_budget.py`'s docstring: "`:exacto` pins provider routing, never price". Unsuffixed ids take OpenRouter's default provider pool, so truncation/401/no-output are properties of the **provider**, not the model. Falsifier: `:exacto` rides showing the same classes at n ≥ 20 (n=6 today — this is the weak leg).
**Process change.** **Do not re-propose the flip — it already shipped (PR#1639) and homelab#1669 (2026-09-14, OPEN, `agent/blocked`) is "the exacto flip re-read against a week of strike rows — standing or reverted".** Post this 158-ride strike table as the evidence #1669 is waiting on, per the brief's dedup-first discipline.
**Expected saving.** 34 strike rides → ~17 at haiku's 11% rate. Rail 2 on the deepseek rows that billed; rail 3 otherwise — plus one model-swap latency per strike avoided.

### F5 — The estimator is sized for 3 rounds; the loop runs a median of 4 and a bound of 5
**Evidence.** The two excerpted artifacts disagree. `estimate_budget.py`: `DEFAULT_ROUNDS = 3  # max review rounds before escalating to a human (workflow.md hazard)`. The README invariant: "**bounded rounds** (max 5 **logic** rounds, ADR-127)". Observed: median distinct logic rounds **4** (mean 3.81), **24 of 36** round-detailed tasks (67%) exceed 3, six exceed 5. Calibration confirms it: **sm mean |error| 0.485 (n=4) vs md 0.051 (n=3)** — 9.5×; homelab#1041 spent **$0.5245 against a $0.50 sm cap** (calibration_error 1.049); both blocked tiered rows are sm (#1041, sleep-tracking#71 at 0.544). Four `budget-exhausted*` strikes in the ledger (homelab#892, #779, #1151, #778), each costing a ride plus a model swap.
**Mechanism (falsifiable).** `cost ≈ rounds × requests/round × …` at 3 rounds is 0.6–0.75× the observed count; the 2.0 headroom (retro r3 F5, #258) absorbs that only at md and above, so sm lands *at* the cap and the OpenRouter 403 fires mid-run. Falsifier: sm rows clustering well under cap once round count is controlled for.
**Process change.** `agents/estimate_budget.py`: `DEFAULT_ROUNDS = 3` → `5`, and re-point the comment from "workflow.md hazard" to ADR-127's bound so the two artifacts agree.
**Expected saving.** Rail 2/3: removes the 4 budget-403 strikes and their swap rides (cents each). Rail 1 conditionally: `agent/blocked` is defined as "budget escalate / max rounds / ambiguous" — one budget-escalate park avoided is a full E, **~€20–30**; observed once (#1041).

### F6 — The fleet-strike filing surface files duplicates and files unkeyable classes
**Evidence.** `fleet-strike: error_class=goose-32602-truncation` filed **twice on 2026-09-14** (#1705 CLOSED, #1707 still OPEN). `fleet-strike: error_class=unknown` filed **three times in 14 days** (#1622 09-07, #1642 09-13, #1653 09-14). #1712 (filed and merged 09-14) fixed the "re-files a RESOLVED class until the 24h window lapses" half — #1705/#1707 were filed the same day. The brief's rule: *"Dedup first … search open issues for the same gate/`error_class` and extend the existing one instead of filing a second."*
**Mechanism (falsifiable).** The dedup search keys on (gate, `error_class`) among **OPEN** issues; #1705 was closed before #1707 was filed, so the search found nothing. And `error_class=unknown` is unkeyable by construction — sibling of #1775 ("the `job_step` field is silently dropped whenever the step name contains a space (40%…)"). Falsifier: a duplicate pair where both were open simultaneously.
**Process change.** In the README `agent/error` row's STRIKE-channel clause: (a) widen the dedup search to `state:all` inside the 24h window, and (b) make `error_class=unknown` a **hard reject** — attach to the ride's `AGENT_STRIKE:` comment rather than opening an unkeyable issue.
**Expected saving.** 3 board items/14 days a human triages → in-sitting, **€3–8 each ≈ €15/week** — and it restores the dedup invariant every other filing gate depends on.

## Predecessor score

Merged predecessor changes exist: r3 (#256–#259, 2026-08-11), r1 (#927–#932, 2026-08-25), r2 (#1102–#1109, 2026-08-31).

**Did rounds/issue drop? No — it rose 2.1×.** Mean distinct logic rounds by ledger window: **2.45** (pre-08-25, n=20) → **4.38** (08-25…08-31, n=8) → **5.17** (≥08-31, n=12). Mean rides: 2.60 → 5.62 → 5.83.

What moved in the other direction: `agent/blocked` share fell **75% → 38% → 8%**. The honest read is that the predecessor changes did not make tasks cheaper — they **converted parks into completions by spending more rounds**. Under this brief's cost model that is a strongly positive trade (a park costs a full operator E ≈ €20–30; a round costs cents). Both trends are confounded and I will not over-read either: the pre-window is the older emitter vintage (4 scalar-`rounds` rows, 7 with `wall_time_s: 0`), and F1 means the pre-window's blocked count is *inflated* by stale labels — which weakens the blocked-rate improvement, not the rounds rise. The rounds figure is the more reliable of the two because it is computed from round records, not labels.
