# Oracle loop retro r1 — goose (backing model not exposed in-env)

## Summary (≤5 lines)
- 32 ledger tasks, ~30 done / 2 blocked; recorded spend $0.5743, all on `deepseek-v4-flash` rows — every `haiku` row records $0.0 because the claude tier emits `cost_unknown:true` (#22's AGENT_RUN_STATS).
- The ledger itself is the worst offender: ranks 4/7/8 (#29, #43, #42) are **phantom failures** — merged green PRs recorded `failed`/`error_class=unknown` via missing claude-tier finalize (FU-066b); `reviewer_rounds` and `retry_storms` are 0 on all 32 rows despite 44-review PRs and documented 401/403 auth storms.
- Round-burn shifted over time: pre-2026-07-10 it was reviewer whack-a-mole (#1: 3 disjoint CHANGES_REQUESTED sets; fixed by review.md §Maturity — post-policy tasks converge in ≤2 logic rounds); what remains is paperwork/policy gates (#8 spec-declaration round; #47/#66 recipe path-ban deadlocks).
- Wall time is wait time: #8 = 53.8h (stalled review loop, 44 reviews, PR closed unmerged), #45 = 8.9h, #29's ledger wall 3.7h vs a real 32-min PR cycle; 27/32 rows record wall_time 0.
- Infra deaths (git-token TTL vs model pace, key PATCH-expiry, max_tokens=4096 truncation, budget-403) cluster on #1 and were root-caused platform-side; residual risk = an estimator with no pace model (its one real calibration point was ~40% low) and a calibration metric vacuous where populated.

## Findings (ranked, ≤6)

### F1 — Ledger telemetry is systematically wrong or absent; it mis-ranked this very retro
- **Evidence**: 3 of the top-8 pain ranks are bookkeeping artifacts: #29 (exits `[failed,failed]`, CI `[null,null]`, `agent/done` — trail shows a max-turns-80 death, then a *successful* run: PR #48, 97 tests green, merged in 32 min), #43 and #42 (exit `failed`, CI `[null]`, done — each trail shows one run with a full success summary, 110 tests green, PRs #51/#53 merged). #22's meta comment states the mechanism verbatim: *"the claude harness has no agent-finalize/PR-detection yet — it emits only a minimal AGENT_RUN_STATS with no pr_url, so the launcher's PR-open detection blindly fired a strike"* (FU-066b), with `cost_unknown:true`. Repo-wide search: `AGENT_RUN_STATS` on only **2 of 32** task issues (#22, #47); strikes on 9 issues, 8 with `error_class=unknown` (≥4 provably false positives). `reviewer_rounds=0` on all rows vs 21 review events on PR #6 and 44 on PR #13. `retry_storms=0` everywhere vs #1's documented 401 storm ("retried a fatal auth error dozens of times", FU-021) and 403 storm. #66 records CI `[false]` although nothing was pushed — consistent with ci_sequence being the worker's self-reported `ci_passed` from the fix.yaml response schema, not GitHub checks.
- **Mechanism**: the ledger is scraped from launcher bookkeeping that is (a) dispatcher-lifetime-coupled (FU-043, 3 confirmed occurrences on #1 alone), (b) blind on the claude tier (no finalize → false strike → `failed` exit + null CI), and (c) has no emitters at all for reviewer/storm fields. Falsifiable: rows with complete stats (#22, #47) should be accurate and stats-less rows wrong — which matches observation.
- **Process change**: make `agent-finalize` the single ledger writer and port it to the claude tier: every worker pod posts one full `AGENT_RUN_STATS` JSON (exit_status, pr_url, CI verdict from the PR check API, wall_s, cost or explicit `cost_unknown`, reviewer-verdict count, storm count) as its terminal act, decoupled from dispatcher lifetime (closes FU-066b + FU-043); ledger rows are built from that line only, never from launcher inference. Artifact: homelab `agent-session.sh`/agent-finalize + the ledger schema.
- **Expected saving**: eliminates ~4 false strikes per 32 tasks (12%), each currently costing ~1 wrong model-chain walk + 1 human correction post (#22, #29 needed operator annulments); makes reviewer_rounds/retry_storms measurable for every future retro; prevents ≥3 of 8 deep-dive slots being wasted on phantoms.

### F2 — Wall-time outliers are queue/review stalls, not model runtime
- **Evidence**: #8 wall_time 193579s (53.8h) for 2 clean green rounds whose entire round-2 work product was a PR-body "Spec changes:" section + one fixture reconciliation; its trail says *"coordinator reconcile: picking up the stalled review loop on PR #13"*; PR #13 accumulated 44 review events and closed unmerged (work re-landed via PR #37). #45 wall 32207s (8.9h). #29 ledger wall 13370s vs PR #48 created→merged in 32 min. #1 ledger 13762s vs PR #6 open→merged ~7h. 27/32 rows record wall_time_s=0.
- **Mechanism**: reflexes are edge-triggered with no level-triggered timeout — when the review reflex stalls, nothing notices until a coordinator tick or a human; ledger wall_time is comment/tick-derived, so it inflates with idle waiting and collapses to 0 for same-tick tasks. Falsifiable: correlate PR push timestamps with review verdict timestamps on #8/#45 — expect multi-hour gaps with zero activity.
- **Process change**: add a stale-stage sweep clause to `coordinator-scan.sh`: each tick, if a task PR is green+current with no review verdict >60 min since last push → re-trigger the review reflex; if CHANGES_REQUESTED is unattended >4h → run arbitration; if a PR accumulates >2 CHANGES_REQUESTED → post a whack-a-mole alert; write wall_time from label-transition timestamps, not comment scraping. Artifact: `coordinator-scan.sh` sweep clause (+ ledger wall_time definition).
- **Expected saving**: the four outlier rows hold ~70h of wall (#8 53.8 + #45 8.9 + #29 3.7 + #1 3.8); bounding each stall at ≤1 tick recovers roughly 55–65h — >80% of outlier wall time — at zero token cost.

### F3 — A whole round burned on a paperwork gate the reviewer enforces post-hoc (#8 pattern)
- **Evidence**: #8 round 2 exists solely because round 1 edited three `specs/` fixture files while the PR body declared "No spec changes" — the reviewer is rubric-bound to request-changes on any unflagged specs/ edit (review.md rule 2, *"the one gate that holds regardless of the pre-prod merge-forward bias"*). That one omission consumed a full worker round + review cycle + the F2 stall. fix.yaml already mandates the "Spec changes:" heading — the worker didn't do it, and nothing mechanical catches it before the expensive LLM review does.
- **Mechanism**: a purely syntactic invariant (diff touches `specs/**` ⇔ PR body contains "Spec changes:") is enforced by an LLM reviewer hours after push instead of a seconds-long CI lint. Falsifiable: the check needs no judgment — grep diff paths + body.
- **Process change**: extend `scripts/spec-evidence-lint.py` (or a 10-line job in `.github/workflows/ci.yaml`) to fail the PR when `git diff --name-only origin/master` hits `specs/**` and the body lacks a "Spec changes:" heading; then soften review.md rule 2 to "CI enforces declaration; review the flags' honesty". Artifact: `scripts/spec-evidence-lint.py` + `.agents/review.md` rule 2 text.
- **Expected saving**: 1 worker round (~$0.05–0.13 at deepseek priors, or a subscription slot) + 1 reviewer cycle + the multi-hour/day stall per occurrence; observed 1/32 tasks, but it is the last remaining hard-block class under PRE-PROD merge-forward — removing it lets reviews be pure approve-with-follow-ups (zero round-trips for this class).

### F4 — Recipe path-bans contradict lane charters and are discovered by burning dispatches (#47/#66 class)
- **Evidence**: #47 hit the `.agents/fix.yaml` `chart/` ban twice — the 2026-07-18 re-block was a verbatim replay of the first ("re-dispatching now would replay the identical wasted/rule-violating round"); resolved only by a human amendment (master 3f3df8b) after ~3 days of queue wall. #66 then hit the *same class* on `.github/` (ban vs `track/chassis` charter, which lists `.github/workflows/ci.yaml` as chassis-owned per specs/TRACKS.md) plus a hard token-scope constraint — a full worker round was dispatched just to re-derive the conflict and stop (correctly); the issue is terminally `agent/blocked`. Both conflicts were statically knowable before any dispatch.
- **Mechanism**: fix.yaml's forbidden-path list and the per-lane ownership in `specs/TRACKS.md` drift apart, and nothing intersects an issue's deliverable paths with the ban list (or the token's push scope) at queue time — so the conflict surfaces as a wasted coordinator block cycle or a wasted worker round. Falsifiable: for both #47 and #66, the issue body names the forbidden paths verbatim before dispatch.
- **Process change**: add a pre-dispatch clause to `coordinator-scan.sh` (next to the FU-087 Depends-on gate): extract repo paths from the issue body, intersect with fix.yaml's forbidden set (+ static note that `.github/workflows/**` needs a `workflows`-scoped token); on non-empty intersection, post the named policy-conflict hold comment *without* dispatching, so the human decision happens before any round exists. Artifact: `coordinator-scan.sh` pre-dispatch clause (no fix.yaml edit — the human gate stays).
- **Expected saving**: ~2/32 tasks (6%) hit this class; per hit it saves 1–2 coordinator block cycles + 1 worker round (subscription pod ~30–60 min) + 3–4 days of queue wall (#47) or a terminal block stranding a deliverable (#66).

### F5 — Dispatch envelope (TTL/cap/estimate) has no pace model; calibration is blind on the subscription lane
- **Evidence**: all on #1 (2026-07-09): hy3:free died of token-expiry (2917s pace > 60-min git-token TTL, zero artifact); hy3 died of budget-403 — real spend $0.5086 vs cap $0.50 vs **est $0.3024** (estimate ~40% low, the only real calibration event in the trails); a re-mint PATCH silently kept the old key expiry (worker died at the key's real expiry "to the second"); three truncation deaths at 14781/15267/16322 chars (root-caused to a `max_tokens=4096` default, proxy-floor fixed). Five dead dispatches (~7h wall, $0.036+ direct loss) before the first logic round. Ledger side: `calibration_error` null for 29/32 rows and `0.0` for #108/#107/#121 — rows whose actual cost is $0.0 by construction (`cost_unknown:true`), so the metric reports perfect calibration where it measures nothing.
- **Mechanism**: the estimator prices a (model, tier) pair from a cost point-estimate (cap ≈1.5–1.65×est) but never checks whether the model's *duration* distribution fits inside min(git-token TTL, key TTL); slow models are structurally unable to deliver a PR in-window regardless of cap. Falsifiable: plot historical per-model run durations against the 3600s TTL — hy3 tiers sit past it, deepseek (405s-class) fits.
- **Process change**: add a pace gate to the budget estimator's dispatch decision: dispatch a (model, task-tier) pair only if p50-observed-duration ×1.5 < min(git TTL, key TTL), else skip to the next chain entry at estimate time (the priors already exist — #1's strike note quotes "deepseek 405s-class, $0.05–0.11/run"); set caps from p90 observed cost per (model, tier); emit `calibration_error` only on metered lanes (suppress the vacuous 0.0 on `cost_unknown` rows). Artifact: the budget estimator (+ ledger field semantics).
- **Expected saving**: prevents the #1-class 5-dispatch failure (~7h wall + chain strikes that nearly forced `agent/blocked` on a sound task); removes hy3-class structural mismatches at estimate time instead of by strike; makes the calibration field honest (currently 3/3 populated values are noise).

### F6 — Dispatch races and stale labels: edge-triggered reconcile misfires
- **Evidence**: #52 — two pods dispatched for the same issue/round 46–85s apart (FU-042 pre-flight checks only `Running` pods; both were ContainerCreating), one omitting `--docker` and guaranteed to fail CI; averted only because the second dispatcher deleted its own pod. #47 — a redundant worker dispatched onto already-complete PR #58 because the label was stale `agent/in-progress`; the anomaly circuit-breaker then false-positived (AGENT_ERROR) and the recipe clause had to be fixed on master. #1 — round-3 dispatch notes *"label agent/in-progress was stale"*. #108 — reconcile found PR #111 merged and relabeled in-progress→done by hand ("stale from the round-1 claim").
- **Mechanism**: dispatch pre-flight and label flips are edge-triggered snapshots; pod-existence checks miss pre-Running phases, and terminal labels depend on a tick happening to notice the merge. Falsifiable: any window with two concurrent coordinator invocations can double-dispatch (observed 1/32), and every merged-before-tick task carries a stale label (observed ≥3).
- **Process change**: in `coordinator-scan.sh`/`agent-session.sh` pre-flight: select worker pods by label (`agent-issue=<n>`) across *all* phases (including ContainerCreating) before minting a round; add a per-tick label reconcile rule (open PR referencing issue ⇒ `agent/review`; merged PR ⇒ `agent/done`) so terminals never wait on a human noticing. Artifact: `coordinator-scan.sh` pre-flight + reconcile clause (FU-042 follow-up).
- **Expected saving**: ~1 double-dispatch per 32 tasks (1 wasted pod boot + a near-miss CI-failed round ≈ $0.15), 1 breakered redundant dispatch (#47), and the recurring stale-label reconcile comments (≥3 observed) plus the misread risk they inject into every level-triggered tick.
