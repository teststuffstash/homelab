## Goal

The gateway stops learning the OpenCode Go account's exhaustion from a ride's death. Every paid Go model draws **one account allowance** (PR #3105, `latch_scope: account`); the vendor publishes that allowance's reading (`GET /zen/go/v1/usage` → `{rolling, weekly, monthly: {status, percent, resetsAt}}`, probed 200 with the gateway's key on 2026-11-01), and the `opencode` harness does not survive the 429 that today is the gateway's only signal (three retries, then `Error: Go usage limit exceeded`, exit — 2026-11-01 01:39–01:47Z, three worker rides, #3095).

**Acid test:** replay the 2026-11-01 01:39Z condition against a fake usage endpoint reporting the rolling window at its ceiling — `POST /sessions` for a worker defers the opencode rail `quota-limited` with `retry_after_s` = the rolling window's `resetsAt` − now, and no session is admitted onto a Go cell; and a session whose last relayed answer was a Go 429, reported `unknown` by its consumer, leaves zero counted strikes on the task.

Design pins the children elaborate:
- **A Go twin of [GW-CODEX-HEADROOM](https://gateway-specs.homelab.teststuff.net/endpoints/openai-responses/#gw-codex-headroom)**, not a new mechanism: the same snapshot (strictly-newer, valid report replaces), the same verdicts (`admit` / `quota-unknown` / `quota-stale` / `quota-limited`), the gateway polling with its own Go key (the credential owner observes its own account).
- **Opt-in by policy, so the code ships before the policy does:** a policy with no `rails.opencode.headroom` block admits the Go rail exactly as today (the window draw + the account latch); the loader refuses unknown keys, so the deployed `policy.json` gains the block only after the image that reads it is deployed (post-launch).
- **A capacity death is no verdict on the model:** the gateway owns the transport fact first-hand (GW-SESSIONS-OUTCOME already writes no strike for the 429 itself); a consumer's outcome on such a session writes none either.

Authored by island intake from teststuffstash/homelab#3108 (operator-filed; the ⚑ gap PR #3105 raised on GW-SESSIONS-ADMIT).
