## Deliverable
The OpenRouter catalog leg keeps every benchmark row it already reads (the MCP `list-benchmarks` answer, source `artificial-analysis`) in its persisted snapshot and serves them on `GET /catalog/openrouter`.

Island: gateway. First child of the runtime-tiers Goal: the tier derivation needs the benchmark rows of all four rails' candidates in the gateway's own store, and today the leg reads the whole feed every 6 h and keeps only the candidates' rows (`sources.benchmarks.rows` holds the count). The operator's text behind it (2026-11-12, on the re-cut's exec into `deploy/openrouter-proxy`): "is this the best solution we can come up with? exec into a pod? Why not do it properly with interfaces, S3, database, etc?"

## Acceptance
1. `GW-CATALOG-OR` on `gateway/specs/endpoints/catalog.md` carries the key rows below, grown to the boundary rows the pinned process asks for; the refresh keeps every benched row, ranked or not, and the candidate set (ranked ∩ benched) is unchanged by it.
2. `GET /catalog/openrouter` answers a `benchmarks` object in a shape `catalog.schema.json` names (`openrouter_output` and `$defs.openrouter_snapshot`): per id its `intelligence`, `coding`, `agentic` (a null stays null) — the row "the view's shape is the schema's" passes with the new key required.
3. A failed or unparseable benchmarks read keeps the last good benched set with the rest of the snapshot, and the set survives a restart (the rows below).
4. No fixture file is edited by hand: the unranked row comes from the world (the fake serves the recorded ranking without one id), never from a row typed into `tests/fixtures/openrouter-catalog/`.
