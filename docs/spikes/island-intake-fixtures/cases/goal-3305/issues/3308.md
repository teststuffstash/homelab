## Deliverable
`POST /sessions` walks the derived tier lists instead of the policy's, and holds a rail that has no derivation — with none on any rail, every session defers until the first derivation completes.

Island: gateway. Third child of the runtime-tiers Goal (the cut-over). The operator's ruling (2026-11-12) on what a session walks when the gateway holds no derivation — defer every session until the first derivation completes, or keep seed lists in the policy: "2 defer".

## Acceptance
1. `GW-SESSIONS-ADMIT` on `gateway/specs/endpoints/sessions.md` carries the key rows below; the walk's order, overrides, harness rule, `prefer` and the rail choice are unchanged — only where a tier's list comes from changes.
2. A rail with no derivation is held with the typed defer `tiers-underived` (in `sessions.schema.json`'s defer reasons) and a `retry_after_s`; the walk moves to the role's next rail; every rail held → the answer is that defer.
3. The policy loader accepts a policy with and without `rails.opencode.models` / `rails.openrouter.models` lists; when present they order nothing. `anthropic` and `codex` lists stay required (they declare the candidates).
4. A restart on a file store dispatches from the stored derivation without waiting for a refresh; a restart on an empty or `:memory:` store defers until the first derivation.
5. `GET /catalog/tiers` `equals_walked` is true on every tier once the walk reads the derivation; the `GW-MODEL-TIERS` row that says so is added.
