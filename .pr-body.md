Fixes #827

## Finding

**#791's deliverable 3 was mis-stated.** The claim that "the launcher's harness derivation stops forcing goose for OR models" assumes OpenRouter models need a derived harness at all — but for OpenRouter, **harness is a choice, not a property of the model id.** Goose, opencode, and claude all serve OpenRouter today. `model_id.py` correctly returns `harness: ""` for every OpenRouter model, leaving the choice to the caller's `--harness` flag.

## Evidence

### `--harness claude --model openrouter/...` already works end-to-end

Verified on master:

```
$ python3 agents/model_id.py --shell "openrouter/anthropic/claude-sonnet-4-20250514"
MODEL_RAIL=openrouter MODEL_HARNESS='' MODEL_MODEL=anthropic/claude-sonnet-4-20250514
```

`agent-session.sh:511`: `[ -z "$MODEL_HARNESS" ] || [ -n "${HARNESS_SET:-}" ] || HARNESS="$MODEL_HARNESS"`

With `MODEL_HARNESS=""` (all OR models):
- If `HARNESS_SET` is set (from `--harness`) -> the explicit harness is preserved
- If `HARNESS_SET` is unset -> the empty derivation is skipped, default harness (`opencode`) stays

### Existing tests already pin the parity

- **`model-id-test`** - 9 parser cases + proxy drift pin, all pass with `harness: ""` for every OR case
- **`router-self-test`** - OK; line 2086 asserts `resolved == {"rail": "openrouter", "harness": "", "model": "inclusionai/ling-3.0-flash:free"}`

### New tests added

2. `HARNESS_SET=1` preserves the explicit harness choice

Plus subscription comparison (`claude/haiku` -> `harness=claude` triggers the override path).
