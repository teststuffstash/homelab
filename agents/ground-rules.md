- **Install tools ONLY via devbox.** Missing a CLI? Add it to `devbox.json` (`devbox add <pkg>@<ver>`) then `devbox install` — reproducible, and exactly what CI runs. NEVER `curl`/download a binary: `.devbox/` is read-only and a hand-placed binary isn't on CI's PATH, so the gate goes red though it 'worked' for you.
- **Prior-art before creating anything named** (doc, script, tracker entry) IN THIS REPO: grep the repo's docs/trackers by keyword first — extend, don't duplicate.
- **Pre-flight before opening a PR: `devbox run diff-ci`** — runs exactly the CI gates your diff can affect (path→task map in `scripts/diff-ci.sh`), so a red lands on your desk in seconds instead of a CI round-trip later. CI stays the authority; a diff-ci pass is not a merge claim.
- **Machine markers are launcher/scan-owned.** NEVER write one in any comment or body: `<!-- agent-summary -->`, `<!-- agent-event … -->`, `state-fp:`, `<!-- agent-budget-refusal -->`, `<!-- standing-aside … -->`. Post progress as plain text or not at all; the ride's own bookkeeping lands via finalize.
- **An escalation asking a human for a manual/console action must first check the DECLARED record for that domain and cite what it says.** For GitHub App permissions that is `docs/github-apps.yaml` + the live `/apps` matrix (a quiet `GithubAppPermissionDrift` alert means declared == live). And a 403 under an App-minted token is a **mint** question before it is a **grant** question: tokens carry only the subset the generator/broker `permissions:` block requested, so "the App lacks X" is refuted by one grep when X is declared. homelab#1038 is the cost of skipping this: 4 false review blocks, 2 futile arbitrations, and an operator escalation for a permission granted six weeks earlier.
- **The two GitHub permission-failure signatures, and what each actually says** (reproduced live, homelab#1038): REST `403 "Resource not accessible by integration"` NAMES the needed permission in a response header `gh` swallows — re-run with `gh api -i` / `curl -si` and read `x-accepted-github-permissions` (e.g. `issues=read`). GraphQL **lies by omission**: the same missing permission returns `NOT_FOUND`/`null`, byte-identical to the object not existing — never conclude nonexistence from GraphQL alone under an App token; cross-check REST, which fails honestly and names the permission.
- **blockedBy filing-edge on every filing door (homelab#1152)**: when a SEAT/jail-session filing wedges live work, wire the native `blockedBy` edge FROM the stuck issue in the same act (`gh api -X POST repos/<slug>/issues/<STUCK>/dependencies/blocked_by -F issue_id=<FILED's numeric .id>`), and such defects queue immediately, master-lane, hotfix-class. The miss that proved it: homelab#1108 was filed wedging oracle-fleet#285 with no edge — hand-wired two hours later.
- **Classify your `Touches:` footprint at every filing door (homelab#1207, #1102 leg 1)**: before filing, run the footprint you're about to declare through `classify_touches()` — source `agents/footprint.sh` and call `classify_touches <footprint>`, or run `scripts/goal-lint.sh <owner/repo> <goal>` over a Goal tree, which does this for you. A `codeowner-author` verdict (the ❌ set: `.github/`, `.agents/`, `devbox.json`/`.lock`, `scripts/`), or a footprint intersecting `scripts/pin-only-lint.sh`'s `GUARDED` set, means no worker can ever deliver it as a PR — file the issue **UNQUEUED** (no `agent/queued`) and write the verdict as a plain sentence in the body, naming the classifier (never a new `Key:` body line — ADR-122 collapses the body grammars into one block; prose is the record here). homelab#1056 sat `agent/queued` all morning on exactly this, visible only in the scan log — the point of this rule is that the issue itself carries the verdict.
