OUT - **The two GitHub permission-failure signatures, and what each actually says** (reproduced live, homelab#1038): REST `403 "Resource not accessible by integration"` NAMES the needed permission in a response header `gh` swallows — re-run with `gh api -i` / `curl -si` and read `x-accepted-github-permissions` (e.g. `issues=read`). GraphQL **lies by omission**: the same missing permission returns `NOT_FOUND`/`null`, byte-identical to the object not existing — never conclude nonexistence from GraphQL alone under an App token; cross-check REST, which fails honestly and names the permission.
